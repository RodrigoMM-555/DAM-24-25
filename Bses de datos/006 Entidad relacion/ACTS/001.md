A partir del diagrama ER proporcionado podemos identificar cuatro entidades principales: Cliente, Pedido, LineaPedido y Producto. Cada entidad tiene un identificador id y una serie de atributos. El diagrama muestra que un cliente puede realizar varios pedidos (relación uno a muchos), que un pedido pertenece a un solo cliente, que un pedido puede tener varias líneas de pedido y que cada línea de pedido relaciona un pedido con un producto, resolviendo así una relación de muchos a muchos entre pedidos y productos mediante la entidad intermedia de LineaPedido.

Un ejemplo seria el de un cliente llamado Juan Pérez que realiza un pedido. Ese pedido puede incluir varios productos distintos, y cada uno de ellos se representa como una línea de pedido diferente que enlaza el pedido con un producto específico, como por ejemplo un portátil o un ratón.

La base de datos en SQL con las tablas, identificadores y relaciones seria la siguiente:
``
CREATE TABLE cliente (
  id INT PRIMARY KEY,
  nombre VARCHAR(255),
  apellidos VARCHAR(255),
  email VARCHAR(255)
);

CREATE TABLE producto (
  id INT PRIMARY KEY,
  nombre VARCHAR(255),
  precio VARCHAR(255)
);

CREATE TABLE pedido (
  id INT PRIMARY KEY,
  fecha VARCHAR(255),
  cliente_id INT,
  CONSTRAINT fk_pedido_cliente FOREIGN KEY (cliente_id)
    REFERENCES cliente(id)
);

CREATE TABLE lineapedido (
  id INT PRIMARY KEY,
  pedido_id INT,
  producto_id INT,
  CONSTRAINT fk_lineapedido_pedido FOREIGN KEY (pedido_id)
    REFERENCES pedido(id),
  CONSTRAINT fk_lineapedido_producto FOREIGN KEY (producto_id)
    REFERENCES producto(id)
);
``

Ùna vez definida la base de datos en SQL podemos usar python para crear clases que representen las entidades y nos permitan incluirlas mas facilmente.
``
class Cliente:
    def __init__(self, id, nombre, apellidos, email):
        self.id = id
        self.nombre = nombre
        self.apellidos = apellidos
        self.email = email

    def __repr__(self):
        return f"Cliente(id={self.id}, nombre='{self.nombre}', apellidos='{self.apellidos}', email='{self.email}')"


class Producto:
    def __init__(self, id, nombre, precio):
        self.id = id
        self.nombre = nombre
        self.precio = precio

    def __repr__(self):
        return f"Producto(id={self.id}, nombre='{self.nombre}', precio={self.precio})"


class Pedido:
    def __init__(self, id, fecha, cliente):
        self.id = id
        self.fecha = fecha
        self.cliente = cliente
        self.lineas = []

    def agregar_linea(self, linea):
        self.lineas.append(linea)

    def __repr__(self):
        return f"Pedido(id={self.id}, fecha='{self.fecha}', cliente={self.cliente.nombre})"


class LineaPedido:
    def __init__(self, id, pedido, producto):
        self.id = id
        self.pedido = pedido
        self.producto = producto

    def __repr__(self):
        return f"LineaPedido(id={self.id}, pedido={self.pedido.id}, producto={self.producto.nombre})"
``

Una vez tenemos el codigo podemos probarlo creando instancias relacionadaas entre si, como un cliente que hace un pedido de varios productos.
``
cliente1 = Cliente(1, "Juan", "Pérez", "juan@email.com")

producto1 = Producto(1, "Portátil", 899.99)
producto2 = Producto(2, "Ratón", 19.99)

pedido1 = Pedido(1, "2026-01-03", cliente1)

linea1 = LineaPedido(1, pedido1, producto1)
linea2 = LineaPedido(2, pedido1, producto2)

pedido1.agregar_linea(linea1)
pedido1.agregar_linea(linea2)

print(cliente1)
print(pedido1)
print(pedido1.lineas)
``

Al analizar las relaciones, se observa una relación uno a muchos entre Cliente y Pedido, ya que un cliente puede tener varios pedidos. También existe una relación uno a muchos entre Pedido y LineaPedido, porque un pedido puede contener varias líneas. Finalmente, la relación muchos a muchos entre Pedido y Producto se resuelve mediante la entidad LineaPedido, que actúa como tabla intermedia tanto en el modelo ER como en la base de datos SQL y en las clases Python.

En un caso real como una tienda en línea, este modelo ER es fundamental para gestionar clientes, pedidos y productos de forma ordenada. Tambien permite saber qué cliente ha realizado cada pedido, qué productos contiene cada pedido y mantiene la información organizada y coherente. Aplicando estos conceptos, se puede diseñar una base de datos robusta y unas clases en Python que reflejen fielmente la realidad del negocio, facilitando tanto el almacenamiento de datos como su uso dentro de una aplicación.
