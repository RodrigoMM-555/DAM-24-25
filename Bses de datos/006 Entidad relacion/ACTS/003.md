El diseño de un diagrama Entidad-Relación permite representar de forma clara cómo se organiza la información dentro de una base de datos y cómo se relacionan los distintos datos entre sí. En este caso se modela una situación muy común en sistemas reales, donde una persona puede disponer de varios números de contacto asociados.

La entidad Cliente representa a las personas registradas en el sistema. Contiene los datos básicos necesarios para su identificación, como un identificador único y la información personal. Esta entidad es la principal del modelo, ya que el resto de la información gira en torno a ella.

La entidad Telefono representa los números de contacto. Se define como una entidad independiente porque un mismo cliente puede tener varios teléfonos distintos y cada uno posee características propias, como el tipo o el número. Para mantener la relación con el cliente, se incluye un atributo que referencia al identificador del cliente.

La relación entre ambas entidades es de uno a muchos, ya que un cliente puede tener varios teléfonos asociados, mientras que cada teléfono pertenece únicamente a un cliente. Esta relación se refleja en el diagrama uniendo ambas entidades y estableciendo la cardinalidad correspondiente.

Cliente 1 ────── N Telefono


Como conclusión, este modelo ER muestra cómo organizar correctamente una relación uno a muchos en una base de datos real, evitando la duplicación de información y permitiendo una gestión flexible de los datos. Este tipo de diseño es especialmente útil en aplicaciones donde es necesario almacenar múltiples formas de contacto para una misma persona, como agendas, sistemas de clientes o aplicaciones de gestión empresarial.
