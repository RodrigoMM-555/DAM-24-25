En esta actividad se trabaja el diseño de una base de datos relacional completa a partir de un caso práctico sencillo, una tienda de patos de goma, junto con su integración básica en una aplicación web con Flask. El objetivo es afianzar conceptos como claves primarias y foráneas, orden correcto de inserción de datos, uso de vistas para simplificar consultas y separación entre lógica de datos y presentación, incorporando además buenas prácticas habituales y detectando errores comunes.

El diseño del script SQL es la base de todo el sistema. Definir correctamente las tablas “madre” y “hija” evita problemas de integridad referencial. Un error frecuente es crear las tablas en desorden o no definir las FK, lo que rompe la relación entre datos.
``
-- Creación de la base de datos
CREATE DATABASE tienda_patos;
USE tienda_patos;

-- Tabla de categorías de patos
CREATE TABLE categorias_pato (
    id INT AUTO_INCREMENT PRIMARY KEY,
    nombre VARCHAR(100) NOT NULL,
    descripcion TEXT
);

-- Tabla de clientes
CREATE TABLE clientes (
    id INT AUTO_INCREMENT PRIMARY KEY,
    nombre VARCHAR(100) NOT NULL,
    email VARCHAR(100) UNIQUE NOT NULL
);

-- Tabla de productos (patos de goma)
CREATE TABLE productos_pato (
    id INT AUTO_INCREMENT PRIMARY KEY,
    nombre VARCHAR(100) NOT NULL,
    precio DECIMAL(6,2) NOT NULL,
    categoria_id INT,
    FOREIGN KEY (categoria_id) REFERENCES categorias_pato(id)
);

-- Tabla de pedidos
CREATE TABLE pedidos (
    id INT AUTO_INCREMENT PRIMARY KEY,
    cliente_id INT,
    fecha DATE,
    FOREIGN KEY (cliente_id) REFERENCES clientes(id)
);

-- Tabla de líneas de pedido
CREATE TABLE lineas_pedido (
    id INT AUTO_INCREMENT PRIMARY KEY,
    pedido_id INT,
    producto_id INT,
    cantidad INT NOT NULL,
    FOREIGN KEY (pedido_id) REFERENCES pedidos(id),
    FOREIGN KEY (producto_id) REFERENCES productos_pato(id)
);

-- Tabla de stock actual
CREATE TABLE stock_actual (
    producto_id INT PRIMARY KEY,
    cantidad INT NOT NULL,
    FOREIGN KEY (producto_id) REFERENCES productos_pato(id)
);

-- Tabla de movimientos de stock
CREATE TABLE movimientos_stock (
    id INT AUTO_INCREMENT PRIMARY KEY,
    producto_id INT,
    tipo_movimiento VARCHAR(50),
    cantidad INT,
    fecha DATE,
    FOREIGN KEY (producto_id) REFERENCES productos_pato(id)
);

-- Vistas para mostrar información relacionada
CREATE VIEW vista_productos AS
SELECT p.id, p.nombre, p.precio, c.nombre AS categoria
FROM productos_pato p
JOIN categorias_pato c ON p.categoria_id = c.id;

CREATE VIEW vista_pedidos AS
SELECT pe.id AS pedido, cl.nombre AS cliente, pe.fecha
FROM pedidos pe
JOIN clientes cl ON pe.cliente_id = cl.id;

CREATE VIEW vista_lineas_pedido AS
SELECT lp.id, pe.id AS pedido, pr.nombre AS producto, lp.cantidad
FROM lineas_pedido lp
JOIN pedidos pe ON lp.pedido_id = pe.id
JOIN productos_pato pr ON lp.producto_id = pr.id;

-- Inserción de datos (orden correcto)

La aplicación práctica con Flask permite comprobar cómo este tipo de proyectos se pueden integrar en una web sencilla. Definir rutas claras y separar cada página en su plantilla HTML es una buena práctica que facilita la ampliación futura del proyecto. Un error habitual es mezclar demasiada lógica en el archivo principal o no reutilizar plantillas.
``
from flask import Flask, render_template 

app = Flask(__name__)

@app.route("/")
def inicio():
    return render_template("inicio.html")
  
@app.route("/sobremi")
def sobremi():
    return render_template("sobremi.html")
  
@app.route("/contacto")
def contacto():
    return render_template("contacto.html")

if __name__ == "__main__":
    app.run(debug=True)
``

Las plantillas Jinja2 permiten estructurar el contenido de forma clara y reutilizable. Es importante mantener un diseño simple al principio y centrarse en que las rutas funcionen correctamente antes de añadir estilos o lógica avanzada.
``
<!doctype html>

  </head>
  <body>
    <h1>Tienda de patos de goma</h1>
    <p>Bienvenido a nuestra tienda</p>
  </body>
</html>

Lo aprendido puede aplicarse en futuros proyectos como tiendas online más complejas, sistemas de gestión de inventario o aplicaciones empresariales reales, donde una buena estructura de datos y una arquitectura clara marcan la diferencia en la escalabilidad y el mantenimiento del software.
